# NagramXF 系统级 PIP 倍速按钮图标问题分析与修改方案

> 项目：NagramXF（Android）
>
> 问题范围：Android 系统级画中画（Picture-in-Picture，PIP）窗口中的倍速
> `1×`、`2×` 操作图标明显小于播放/暂停图标。
>
> 当前已知情况：手机和平板均存在相同现象；倍速按钮能够正常显示和响应，主要问题是视觉尺寸偏小；目前尚未确认图标具体采用
> VectorDrawable、Bitmap/Canvas 还是其他方式生成。

------------------------------------------------------------------------

## 1. 问题描述

NagramXF 使用 Android 原生 PIP 窗口，而不是应用完全自绘的悬浮播放器。PIP
窗口中的播放控制及自定义操作由 Android 系统界面（System UI）负责呈现。

目前观察到：

-   播放/暂停按钮显示正常，视觉尺寸较大。
-   倍速按钮显示为 `1×`、`2×`，但视觉尺寸明显偏小。
-   手机和平板均出现该问题。
-   倍速按钮功能本身正常，不需要重做倍速切换逻辑。
-   用户希望保留系统原生 PIP 窗口，不希望整体自绘 PIP 控制界面。

因此，本次工作的目标不是放大整个 PIP
按钮或改造系统窗口，而是改善倍速图标在系统分配的图标区域中的视觉占比。

## 2. 先明确 Android PIP 的能力边界

### 2.1 应用能够控制的内容

通过 `RemoteAction` 提供自定义 PIP 操作时，应用可以提供：

-   图标（`Icon`）
-   操作标题（`title`）
-   无障碍描述（`contentDescription`）
-   点击动作（`PendingIntent`）

应用可以决定图标资源的绘制内容，例如使用矢量图、位图或其他受支持的
`Icon` 类型。

### 2.2 应用不能通过 RemoteAction 直接控制的内容

`RemoteAction` 没有用于设置 PIP
操作按钮宽度、高度、按钮间距或屏幕位置的公开参数。

PIP 操作按钮的容器、布局、最终呈现尺寸及排列由 Android
系统界面决定，并可能随 Android 版本、设备厂商和窗口状态变化。

因此：

-   修改 VectorDrawable 的
    `width`、`height`，不等于能够改变系统按钮容器大小。
-   增大 Bitmap 像素尺寸，不等于系统最终显示的图标一定更大。
-   应用不能通过标准 `RemoteAction` API
    保证倍速按钮与播放/暂停按钮具有完全相同的视觉尺寸。
-   但可以优化图标自身的有效绘制区域，让图形在系统给定的图标区域内更饱满、更清晰。

## 3. 问题可能发生在哪一层

建议按以下链路排查：

``` text
当前倍速状态（1× / 1.25× / 1.5× / 2×）
                 │
                 ▼
         倍速图标生成或资源选择
          │                 │
          │                 ├── VectorDrawable（XML）
          │                 ├── Bitmap / Canvas
          │                 └── 其他 Drawable / Icon
          ▼
       Icon（Android.graphics.drawable.Icon）
                 │
                 ▼
       RemoteAction（图标、标题、描述、PendingIntent）
                 │
                 ▼
       PictureInPictureParams.Builder.setActions()
                 │
                 ▼
       Android System UI 绘制 PIP 操作按钮
```

需要重点判断：倍速图标自身是否只占图标画布的一小部分，以及它与播放/暂停图标是否采用了不同的资源规格、留白比例或绘制方式。

## 4. 源码审计范围

目前尚未确认 NagramXF 当前版本中倍速 `RemoteAction`
的具体实现文件和资源文件，因此不能预先指定某个文件一定需要修改。应先在源码中搜索以下关键词：

``` text
RemoteAction
PictureInPictureParams.Builder
setActions
Icon.createWithResource
Icon.createWithBitmap
PictureInPictureParams
```

建议在仓库根目录执行：

``` bash
grep -RInE \
  'RemoteAction|PictureInPictureParams|setActions|Icon\.createWithResource|Icon\.createWithBitmap' \
  TMessagesProj/src TMessagesProj 2>/dev/null
```

再检查找到的图标资源引用，例如：

``` bash
grep -RInE \
  'speed|rate|play|pause|pip|倍速' \
  TMessagesProj/src/main/res TMessagesProj/src/main/java 2>/dev/null
```

对定位到的代码，需要记录：

1.  倍速 `RemoteAction` 在哪个类、哪个方法中创建。
2.  倍速图标的资源 ID 或生成方法。
3.  播放/暂停图标的资源 ID 或生成方法。
4.  两类图标是否使用相同类型的 `Icon`。
5.  图标是否在不同倍速状态下动态更新。
6.  更新倍速图标时是否重新调用 `setActions()` 更新 PIP 参数。
7.  手机和平板是否共用同一套图标资源。

**注意：** 在没有检查实际源码之前，不应断言当前实现一定是
Bitmap、VectorDrawable 或 TextView。

## 5. 候选原因

### 5.1 图标画布中存在过多透明留白

例如，一个正方形图标画布中，`1×`
字符只占中间约一半区域。系统按整个图标画布缩放后，实际文字就会显得很小。

应检查图形的有效边界，而不是只看资源文件声明的宽高。

### 5.2 文字字形自身的留白和比例

`1×` 是文字组合，其字形边界、字体度量、字重以及 `×`
的实际占比，都可能造成视觉上比播放三角形或暂停竖条更小的效果。

如果当前图标是 Canvas 绘制文字，还要检查：

-   `Paint.setTextSize()`
-   `Typeface`
-   `Paint.Align`
-   `drawText()` 的坐标和基线
-   Bitmap 的宽高和透明边缘
-   绘制内容是否超出画布

### 5.3 倍速图标与播放/暂停图标的资源规范不同

播放/暂停图标可能来自已有的系统风格矢量资源，而倍速图标可能是普通文字或留白较大的自定义资源。即使系统分配相同大小的图标区域，两者的视觉重量也可能明显不同。

### 5.4 系统或厂商对图标的呈现存在差异

PIP 的最终呈现由系统界面控制。不同 Android
版本、厂商系统可能采用不同的图标缩放和布局策略。

手机和平板都出现相同问题，说明值得优先检查应用提供的图标资源；但这并不能单独证明问题一定来自资源，也不能排除系统渲染因素。

## 6. 推荐修改方案

总体原则：

-   保留 Android 原生 PIP。
-   保留现有倍速切换逻辑。
-   不修改 PIP 窗口布局。
-   不尝试通过非公开 API 改变系统按钮尺寸。
-   先只替换或优化倍速图标。
-   手机和平板共用同一套图标，除非实际测试证明需要分辨率适配。

### 方案 A：优化 VectorDrawable（优先考虑）

如果当前倍速图标使用 VectorDrawable，建议直接检查并优化 XML。

重点属性：

``` xml
<vector
    android:width="..."
    android:height="..."
    android:viewportWidth="..."
    android:viewportHeight="...">

    <path
        android:fillColor="..."
        android:pathData="..." />
</vector>
```

优化重点：

-   保持合适的正方形 viewport。
-   减少图形四周不必要的空白。
-   让 `1×` 或 `2×` 的整体轮廓占据更大的有效区域。
-   数字使用清晰、适当粗细的字形。
-   `×` 不要过小，也不要与数字挤在一起。
-   保持与播放/暂停图标相近的视觉重量。
-   不要仅仅增大 `android:width` 和
    `android:height`，因为系统仍可能按自己的规则缩放图标。

### 方案 B：优化 Bitmap / Canvas（如果当前采用此方式）

如果当前代码通过 Canvas 绘制 `1×`、`2×`：

-   检查 Bitmap 尺寸和密度。
-   减少图形四周透明留白。
-   采用清晰的粗体字形。
-   重新调整字体大小、基线和水平位置。
-   避免文字边缘被裁切。
-   使用抗锯齿绘制。
-   不要把"提高 Bitmap 像素尺寸"误认为"改变 PIP 按钮尺寸"。

示意代码（仅用于说明绘制思路，不是 NagramXF 已确认的现有实现）：

``` java
Bitmap bitmap = Bitmap.createBitmap(
        96,
        96,
        Bitmap.Config.ARGB_8888
);

Canvas canvas = new Canvas(bitmap);

Paint paint = new Paint(Paint.ANTI_ALIAS_FLAG);
paint.setColor(Color.WHITE);
paint.setTypeface(Typeface.create(
        "sans-serif",
        Typeface.BOLD
));
paint.setTextAlign(Paint.Align.CENTER);
paint.setTextSize(48);

// 基线位置需要根据实际字体度量微调
canvas.drawText("1×", 48, 62, paint);

Icon icon = Icon.createWithBitmap(bitmap);
```

实际项目中还需要确认 Bitmap
密度、图标尺寸规范、系统是否对透明边缘或位图做二次缩放。不能直接把上述示例当作最终补丁。

### 方案 C：使用单色速度图标

可以尝试使用速度表（Speed /
Speedometer）一类的单色图标，优点是轮廓容易做得饱满，缺点是不能直接显示当前倍速。

如果用户需要一眼看到当前速度，仍建议保留 `1×`、`2×`
形式，或者采用更紧凑的速度图标设计并通过其他界面反馈当前速度。

## 7. 对照测试设计

不要一次改动多个因素。建议建立四组图标对照：

  组别   图标                              目的
  ------ --------------------------------- --------------------------
  A      当前 `1×` / `2×`                  基准
  B      相同内容，但加粗并减少透明留白    判断字形和留白是否是主因
  C      单色速度表图标                    判断非文字图形是否更协调
  D      优化后的紧凑 `1×` / `2×` 矢量图   验证推荐方案

测试时必须保持以下条件一致：

-   使用同一台设备。
-   使用同一个 Android 版本。
-   使用同一个 PIP 窗口尺寸和方向。
-   使用相同的 `RemoteAction` 创建方式。
-   只替换图标资源，不修改其他操作。
-   对比倍速图标与播放/暂停图标的视觉占比。
-   手机和平板分别记录结果。

## 8. 倍速切换和 PIP 更新逻辑

图标优化不应破坏现有功能。

需要确认当前倍速变化后：

1.  播放器速度确实发生变化。
2.  当前倍速状态被正确保存或读取。
3.  `RemoteAction` 的图标随倍速状态更新。
4.  更新后的操作列表重新设置到 `PictureInPictureParams`。
5.  `PendingIntent` 的请求码或 Intent
    标识能够正确区分操作，避免更新后仍触发旧状态。

建议保留现有倍速循环规则，例如：

``` text
1.0× → 1.25× → 1.5× → 2.0× → 1.0×
```

具体档位应沿用 NagramXF
当前实现，不要为了图标调整擅自改变用户已有的倍速行为。

## 9. 不建议采用的方案

### 9.1 不要试图修改系统 PIP 按钮宽高

标准 `RemoteAction` 没有公开的按钮宽高设置接口。修改图标 XML 的宽高或
Bitmap 像素数不能保证改变按钮容器尺寸。

### 9.2 不要整体自绘 PIP 窗口

这会扩大改造范围，并可能影响系统 PIP
的窗口管理、手势、拖动、缩放、返回和兼容性。当前问题只涉及图标视觉大小，没有必要整体重做。

### 9.3 不要仅凭示意图就直接替换资源

必须先定位当前实际使用的图标资源，并比较播放/暂停图标的资源格式和有效绘制区域。

### 9.4 不要使用非公开 System UI 接口

不建议依赖系统私有资源、反射或厂商专有接口来改变 PIP
按钮布局。这类做法兼容性差，也不符合本次最小改动目标。

## 10. 实施步骤与验收标准

### 阶段一：源码定位

-   [ ] 搜索 `RemoteAction` 创建位置。
-   [ ] 找到倍速图标资源或生成代码。
-   [ ] 找到播放/暂停图标资源。
-   [ ] 确认当前图标格式。
-   [ ] 确认倍速更新时的 PIP 参数刷新方式。
-   [ ] 记录涉及文件和方法。

### 阶段二：图标优化

-   [ ] 保留原有 PIP 控制逻辑。
-   [ ] 优先制作紧凑、粗细合适的 `1×` / `2×` 矢量图标。
-   [ ] 减少无效透明留白。
-   [ ] 保持单色、清晰、无多余装饰。
-   [ ] 确保图标状态与当前播放速度一致。

### 阶段三：设备验证

-   [ ] 手机 PIP 显示正常。
-   [ ] 平板 PIP 显示正常。
-   [ ]
    倍速图标不再明显小于播放/暂停图标，或已达到系统渲染条件下可实现的最佳视觉比例。
-   [ ] 点击倍速操作正常。
-   [ ] 切换倍速后图标正确更新。
-   [ ] 快进、快退、播放/暂停不受影响。
-   [ ] PIP 进入、退出、缩放、拖动等行为没有回归问题。

### 验收边界

本项目不承诺突破 Android System UI 对 PIP
操作按钮的尺寸限制。验收目标是：在不自绘整个 PIP 窗口、不使用非公开 API
的前提下，优化倍速图标的有效绘制区域和视觉重量，使它尽可能接近系统播放/暂停图标的视觉大小。

## 11. 最终建议

推荐采用"先审计、再做最小图标替换、最后跨设备验证"的方式。

**第一优先级：** 查明 NagramXF 当前倍速图标究竟是
VectorDrawable、Bitmap/Canvas 还是其他实现。

**第二优先级：**
与播放/暂停图标对照，测量两者在资源画布中的有效绘制边界，判断是否存在透明留白或字形比例问题。

**第三优先级：** 优先尝试紧凑、粗体、有效区域更大的 `1×` / `2×`
矢量图标，保持现有 `RemoteAction` 和倍速业务逻辑不变。

在没有完成源码定位之前，不应直接认定某个文件或某种绘制方式就是问题根源，也不应提交未经设备验证的修改。
